# ADR-005: 重排降级为「第三路信号」，权重固定 < 1

## Status
Accepted (2026-09-20)

## Background
混合检索的常见写法是「召回 → 交叉编码器精排 → 取前 K」，也就是让重排**接管**最终排序：

```python
final = sorted(shortlist, key=lambda i: -rerank_scores[i])[:top_k]   # 坑
```

当重排器在查询语言上力不从心时（最典型：英文 reranker + 中文查询），
它会无人制衡地压掉被 BM25 与稠密检索**双双排第一**的段落。

同源实测（12 篇中英双语文档 × 12 条中文查询，top-1 命中率）：

| 最终排序策略 | top-1 | top-3 |
|---|---|---|
| 纯 RRF，不用重排 | 11/12 | 12/12 |
| 重排直接接管 | **10/12** | 12/12 |
| 二次融合，重排权重 0.5 | **12/12** | 12/12 |

注意 top-3 恒为 12/12：**召回一直是对的，坏的只有排序**。

## Decision
```
stage1 = rrf([bm25, dense], w=[1, 1], k=60)          # 一阶段融合
shortlist = stage1.order[:max(rerank_top_n, top_k)]  # 长度必须 >= top_k
reranked  = sort(shortlist by rerank_score)
stage2 = rrf([stage1.order, reranked], w=[1.0, w_r]) # w_r = 0.5，且必须 < 1
```
- 默认 `NEBULA_RERANK_WEIGHT = 0.5`，做成配置项，**不写死**
- 用 RRF 而非加权分数求和：重排输出 logits，与 RRF 的 `1/(k+rank)` 量纲不可比；
  RRF 只用名次，天然免校准
- 重排的**独立排序完整保留**在 trace 里（`rerank_top`），可解释性不丢
- 写死回归断言：注入**完全倒序**的对抗性重排器，断言一阶段冠军仍是最终第一

不变量为什么不会偶发失败（n>1, w<1）：
```
冠军 = 1/(k+1) + w/(k+n)
亚军 = 1/(k+n) + w/(k+1)
差   = (1-w)·[1/(k+1) − 1/(k+n)] > 0
```
w=1 时该差值为 0，置换型对抗会变成**平局**，断言将随 tie-break 抖动 ——
这是"必须 w<1"的第二个理由。

## Consequences
- 正面：重排成为净收益而非风险；结论有确定性回归护栏
- 负面：永远无法让一个"非常准"的重排器完全主导排序（w→1 被禁止）；
  若确实要 w→1，需同时提供对抗性测试的替代判据
- 附注：实测更大的多语言重排器（1.11GB）在 w=0.5 下仍是 11/12，
  不如 0.15GB 的英文小模型 —— **体积大不等于判得准，先测再换**

## 本项目自测补充（2026-09-20，诚实记录）

用本项目黄金集（12 篇 × 24 条中文查询）做消融，结果**没有区分度**：六种策略全部 24/24。
于是生成困难集（原 12 篇 + 4 篇"关键词枢纽"干扰文档，见 `scripts/make_hard_set.py`），
在困难集上：

| 最终排序策略 | top-1 | top-3 |
|---|---|---|
| 纯 RRF（不用重排） | **23/24** | 24/24 |
| 重排直接接管（错误写法） | **22/24** | 24/24 |
| 二次融合 w=0.25 | 23/24 | 24/24 |
| **二次融合 w=0.50（本项目默认）** | **23/24** | 24/24 |
| 二次融合 w=0.75 | 23/24 | 24/24 |
| 二次融合 w=1.00（等权） | 23/24 | 24/24 |

结论（不美化）：
1. **"重排接管 = 净损害"在本项目复现了**（23 → 22）。
2. **二次融合在 w<1 下与纯 RRF 持平，没有观察到正增益**。
   `bge-reranker-base` 在这套中文集上没能提升 top-1 —— 它不添乱，也没帮上忙。
3. 因此本 ADR 的收益是**风险消除**而非精度提升。若要真正的精度增益，
   应换更强的中文重排器，并在困难集上重跑 `scripts/rerank_ablation.py` 验证后再切换。
4. 代价必须写清：重排单条查询约 **980ms**（16 篇语料，CPU ONNX），
   是检索链路里最慢的一段。追求低延迟时可 `NEBULA_RERANK_ENABLED=0`。

> 附带教训：**评测集必须能区分被评对象**。原始黄金集全策略满分，
> 若只看它就会得出"重排无害也无用、随便怎么配都行"的错误结论。
